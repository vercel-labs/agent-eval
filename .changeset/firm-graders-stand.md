Add a separate verifier and tampering flags. With `verifier: 'separate'`, the agent's file changes are captured as a diff before its sandbox is stopped, and validation runs in a fresh sandbox (same backend, image or runtime, and user) rebuilt from the original fixture, the user's `setup`, the agent's changes, and freshly installed project dependencies, so nothing the agent did to `node_modules`, global binaries, background processes, or test configuration can influence the grader. The agent CLI is installed in the verifier only when the eval imports the judge matchers. Changes to protected paths (the eval files, vitest config and workspace files, `__agent_eval__/**`, `node_modules`, and any `protectedPaths` globs) are not applied and are listed in `result.tampering`, alongside `verifier` and `verifierSandboxId`. With the default shared verifier, `protectedPaths` only reports tampering. Install steps can declare `scope: 'project'` so the verifier re-runs only project dependencies. Both options enter the result-reuse fingerprint only when set; leaving them unset keeps validation exactly as before. The diff is captured with git inside the agent's sandbox, so captured paths are treated as untrusted: anything that isn't a canonical path inside the workspace (an alias like `./EVAL.ts`, or a path outside the workspace) is never replayed and is reported as tampering.
